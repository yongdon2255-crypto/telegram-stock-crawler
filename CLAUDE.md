# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Purpose

Korean stock market intelligence crawler: monitors Telegram channels (증권사 리서치, IT/반도체, 미국주식) **and Korean financial news websites** (via Puppeteer/fetch), extracts text from PDFs and images, summarizes via Claude (OAuth subscription — not API keys), writes structured Markdown into an Obsidian vault, and sends a status report back to the user via Telegram after each cycle.

## Key Commands

```bash
npm install          # install dependencies
node src/auth.js     # first-time only: generate TG_SESSION
npm run monitor      # start polling loop (1h cycle, Telegram + Web)
npm run process      # manually trigger inbox → Obsidian pipeline
npm run backfill     # fetch recent N hours for all channels
node -e "import('./src/web-crawler.js').then(m=>m.runWebCrawl())"  # web crawl only
node src/cli.js add-channel @handle --category 반도체 --large
node src/cli.js list-channels
```

## Architecture

```
Telegram MTProto (gramjs)         Web News Sites (HTML)
    └─▶ src/monitor.js                └─▶ src/web-crawler.js  Puppeteer/fetch
         (polling + slow rule)              └─▶ src/web-fetcher.js  cheerio parsing
              │                                      │
              └──────────────────────────────────────┘
                                   ▼
                          inbox/  (raw JSON, same schema)
                                   │
                         src/handoff.js   moves files into processor queue
                                   │
                         src/processor.js  OCR (pdf-parse + Apple Vision), claude-runner
                                   │
                         src/obsidian.js   writes .md into Obsidian vault
                         src/reporter.js   sends cycle summary to Telegram

config/channels.json    Telegram channel registry — handle, category, large(bool)
config/web-sources.json web source registry — url, selectors, dynamic(bool)
config/settings.json    vault path, retention days, digest schedule (cron)
inbox/                  raw JSON, 7-day TTL
processed/              archive after Obsidian write
```

## Slow Rule (monitor.js)

Channels with `"large": true` in channels.json get a 180s inter-request delay; others 60s. This prevents `FLOOD_WAIT` errors from Telegram.

```js
const delay = channel.large ? 180_000 : 60_000
await sleep(delay)
```

## Reporter (reporter.js)

After each polling cycle, `reporter.js` sends a summary message to `REPORT_CHAT_ID` using the **same gramjs client** (no separate bot token needed):

```
5채널 stock 카테고리 추가 완료 (2026-05-11 00:18 KST)
monitor.js → ok, newMessages=12
다음 cycle: ~60분 후
```

`REPORT_CHAT_ID=me` sends to Saved Messages; use a numeric chat ID for a specific chat.

## Claude Integration (OAuth — no API key)

AI summarization uses the locally installed `claude` CLI via subprocess, not the Anthropic REST API:

```js
import { execFile } from 'node:child_process'
execFile('claude', ['-p', prompt], { timeout: 60000 }, callback)
```

Never add `ANTHROPIC_API_KEY` or `@anthropic-ai/sdk` for the summarization path.

## Obsidian Output Convention

Files land at `{vaultPath}/Stock News/{YYYY-MM-DD}/{category}/{source}_{timestamp}.md` with YAML frontmatter: `source`, `category`, `importance` (상/중/하), `date`.

## Environment Variables (`.env`)

| Key | Purpose |
|-----|---------|
| `TG_API_ID` | Telegram MTProto App ID |
| `TG_API_HASH` | Telegram MTProto App Hash |
| `TG_SESSION` | Serialized StringSession (generated by auth.js) |
| `REPORT_CHAT_ID` | Chat to receive cycle reports (`me` = Saved Messages) |
| `OBSIDIAN_VAULT_PATH` | Absolute path to Obsidian vault |
| `RETENTION_DAYS` | inbox TTL in days (default 7) |

## Scheduling

Mac launchd plist at `~/Library/LaunchAgents/com.crawler.stock.plist` keeps monitor running. See `docs/03-obsidian-setup.md#launchd`.
